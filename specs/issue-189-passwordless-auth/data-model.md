# Data Model: パスワードなしでアカウント登録・ログインする

spec の「主要なエンティティ」に対応する保存先。新しい表は作らず、マイグレーションも無い（すべて Supabase Auth が持つ）。

| エンティティ     | 保存先                                                   | 主な項目                                                                | 規則（spec の要件）                                                                                         |
| ---------------- | -------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| アカウント       | Supabase Auth のユーザー（`auth.users`）                 | id、email、`user_metadata.name`（表示名）、identities（email / google） | メールアドレス 1 つに 1 ユーザー（FR-007, FR-020）。作成時だけ `name` に @ より前を入れる（FR-006）         |
| 案内の見送り回数 | `user_metadata.passkey_prompt_dismissals`                | 0 以上の整数。無ければ 0 と見なす                                       | 3 以上の間は案内を出さない（FR-027）。「あとで」のときだけ 1 増やす（FR-015）。非対応ブラウザでは増やさない |
| パスキー         | Supabase Auth のパスキー（`auth.passkey.list()` で読む） | id、friendly_name、created_at                                           | 1 ユーザーが複数持てる。0 件のときだけ案内を出す（FR-013）。一覧・削除の画面は RT-REQ-1                     |
| ログイン用コード | Supabase Auth の one-time token（アプリからは読まない）  | 6 桁、有効期限 600 秒（ダッシュボードの設定）                           | 期限切れ・誤りは受け付けない（FR-008, FR-022）。再送で前のコードは無効（FR-010）                            |

## 画面の状態（/login・/register のコード入力）

```text
メールアドレス入力 ──コードを送る(成功)──▶ コード入力（送り先を表示）
      ▲   │ 形式エラー・回数制限・送信失敗はその場で表示（FR-011, FR-009, FR-023, FR-025）
      │   └──────────────
      └──「メールアドレスを変える」── コード入力 ──正しいコード──▶ 行き先の判定（R5）
                                         │ 誤り・期限切れはその場で表示（FR-008）
                                         └ 再送（FR-009, FR-010）
```

- 状態は form action の戻り値（`step: 'email' | 'code'` と `email`）で持つ。サーバーに途中の状態は保存しない
