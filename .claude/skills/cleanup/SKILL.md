# cleanup

PRがマージされた後に残るローカルブランチと worktree を片付ける。対象は**マージ済みと確認できたローカルブランチと、それをチェックアウトしている worktree のみ**。未マージの作業を消さないこと、手元の作業を邪魔しないことを最優先にする。

呼ばれ方は2通り:

- **監視モード**（PR番号付き。pr-writer / dev-loop がPR作成直後に呼ぶ）: 「マージ監視」でマージを待ってから「後片付け」を行う
- **即時モード**（引数なし。ユーザーが手動で呼ぶ）: すぐに「後片付け」を行う

## マージ監視

PR作成後、Bashツールで以下を `run_in_background: true`、`timeout: 7200000`（2時間）で起動する。PRの state が `OPEN` でなくなると終了し、セッションが再開される。

```bash
until s=$(gh pr view <PR番号> --json state -q .state) && [ "$s" != OPEN ]; do sleep 60; done; echo "$s"
```

起動したら「PR #<番号> のマージを監視中。マージされたら自動で片付ける」とユーザーに伝え、ターンを終えてよい。

終了時の出力で分岐する:

- `MERGED`: 「後片付け」へ進む（ユーザーの指示は不要）
- `CLOSED`: 未マージでクローズされたので後片付けはせず、その旨を報告する
- タイムアウト: 監視を打ち切った旨と、マージ後に `/cleanup` で手動実行できることを伝える

監視はセッションが開いている間のみ有効。セッション終了後にマージされた分は、次回の即時モードで片付く。

## 後片付け

用語: **メインのワーキングツリー** はリポジトリ本体のチェックアウト（`git worktree list --porcelain` の先頭エントリ）、**worktree** は開発用に `.claude/worktrees/<name>` へ作った作業ディレクトリを指す。

後片付けはメインのワーキングツリーを基点に行い、git コマンドは `git -C <メインのワーキングツリー>` で実行する（worktree の中では `main` に switch できないため）。

1. **手元の状態の確認 — 作業を邪魔する状態なら何も変更せずに止めて報告する**
   - メインのワーキングツリーで `git status --porcelain` に出力がある（未コミットの変更がある）→ 止める。stash や破棄は勝手にしない
   - メインのワーキングツリーの現在のブランチが `main` でも、削除対象（3. で判定するマージ済みブランチ）でもない → 別の作業に移っているので止める

2. **mainを最新化**
   `git switch main` → `git pull --ff-only`。fast-forward できない場合（ローカルの main に独自コミットがある等）は止めて報告する。

3. **マージ済みブランチの判定**
   `git branch --merged main` で main に取り込まれたブランチを列挙する（このリポジトリは merge commit 方式なので、通常はこれで検出できる）。`main` 自身は除外する。

   `--merged` に出ないブランチでも、`gh pr list --state merged --head <branch> --json number,url` でマージ済みPRが見つかるもの（squash/rebase マージや、マージ後にローカルで追加コミットした場合）は候補として扱う。ただし後述の通り強制削除になるので扱いを分ける。

4. **worktree の削除**
   `git worktree list --porcelain` で、3. の削除対象ブランチをチェックアウトしている worktree（メインのワーキングツリー以外）を特定する。
   - その worktree で `git -C <path> status --porcelain` に出力がある → 未コミットの作業が残っているので、worktree もブランチも削除せずスキップして報告する
   - **gitignore 対象のファイルは `git worktree remove` で黙って消える**（`--force` 無しでも拒否されない）。削除前に `git -C <path> status --porcelain --ignored` の `!!` 行を確認する:
     - `.dev-loop/` がある → QAレポート等の記録が失われるので削除せず、メインのワーキングツリーの `.dev-loop/` へ移すか、ユーザーに確認する
     - `.env` がメインのワーキングツリーの `.env` と異なる（`cmp -s` で比較）→ 手元の設定が失われるので、ユーザーに確認する
     - それ以外（`node_modules/`、`.svelte-kit/` 等の再生成できるもの）→ そのまま削除してよい
   - 問題が無ければ `git worktree remove <path>` で削除する（`--force` は使わない。git が拒否したらスキップして報告する）
   - セッションの作業ディレクトリが削除対象の worktree の中にある場合は、先に ExitWorktree（`action: "keep"`）等でメインのワーキングツリーへ戻ってから削除する
   - 最後に `git worktree prune` で、ディレクトリが既に消えている worktree の登録を掃除する

5. **ブランチの削除**
   - `--merged` で検出したブランチ: `git branch -d <branch>` で削除する（git 側でマージ済みを再確認してくれる安全な削除）。確認なしで実行してよい。
   - PRはマージ済みだが `--merged` に出ないブランチ: `git branch -D` が必要になる。`git log main..<branch> --oneline` で main に無いコミットを示し、ユーザーの了承を得てから削除する（worktree の削除も了承後に行う）。
   - 4. でスキップした worktree のブランチは削除できないので、スキップして報告する。

6. **報告**
   削除した worktree とブランチ、了承待ち・スキップしたもの（理由付き）、最終的に残っているローカルブランチと worktree を簡潔に伝える。

## やらないこと

- リモートブランチの削除（GitHub の「マージ後にブランチを自動削除」設定に任せる）
- マージされていないブランチ・PRが open/closed(未マージ) のブランチの削除
- メインのワーキングツリーの `.dev-loop/` ワークスペースの削除
